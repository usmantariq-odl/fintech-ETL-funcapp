## Intentional deployment differences

- Main ETL watches several configured Windows source layouts (legacy source, customer unprocessed folders, inbox folders, vendor/OMC/site trees). At the user's request, the Function now discovers SFTP sites under `/Unprocessed` and reads only `/Unprocessed/<site ID>/input`; the sibling `output` is reserved for outgoing files. Successful archives now go to `/Processed/<site ID>/`. Exception/invalid/unconfigured/regenerated destinations remain at the container root. The optional MagLink root is separate. Windows source paths are not copied into Azure.
- Main ETL assumes six site digits. The Function retains its existing variable-length numeric site support and folder/name matching. Inactive site IDs map to notconfigured, as before.
- Main ETL enables dual-database writes in its current configuration. The Function retains one database. At the user's request, the catalog guard and both private configurations now select `FintechStagDB`. Secondary-database writes remain disabled.
- Standalone CON discovery is commented out in the main orchestrator. This update implements archive-contained CON delivery; it does not invent a standalone CON source.
- Successful and fully failed inputs are preserved as original archives. Partial results are rebuilt from their respective CSV subsets, matching the source's split behavior. Original regenerated markers are preserved in output because the mutating legacy reader now works on a scratch copy.
- MagLink SQL values use typed bulk copy and invariant parsing rather than interpolated statements. The existing mappings, field values and epoch filters are retained. Missing MagLink mappings and CSV site mismatches fail before insertion.
- Bad row conversions in the copied DAL now propagate instead of being silently skipped. Swallowed SQL errors now propagate so infrastructure failures can retry. Archive links, excessive size and unsafe paths are rejected.
- The copied CSV reader and MagLink models remain unchanged. Mapping SQL and conversion rules remain from the source; mapping connections now close reliably and caches refresh every 15 minutes.
- Dead IoT/ADX paths and a disabled TriggerLogicApp path were not revived. They are not active ingestion logic in the source.
